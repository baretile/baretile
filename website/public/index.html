baretile

baretile is a compiler and runtime for Tenstorrent Blackhole. It's written in Python, including the driver that talks to the chip over PCIe.

You write tensor operations, and the compiler turns them into Tensix instructions. The code in baretile/ uses only the Python standard library. The driver runs in userspace and loads our firmware onto the workers. We use Tenstorrent's board firmware for ARC and Ethernet, with no dependency on tt-metal, tt-umd or LLK.

We develop on Tenstorrent's ttsim simulator. We haven't tested baretile on a card yet. Simulator timings don't predict card performance. The roadmap says what we're building first.

Getting started

You'll need Linux, Python 3.12 or later, and clang with a RISC-V target and lld. On Debian and Ubuntu, sudo apt update && sudo apt install python3-venv clang lld curl git installs them. Install baretile in a virtual environment, download the simulator and check the setup:

python3 -m venv baretile-env
. baretile-env/bin/activate
python3 -m pip install baretile
python3 -m baretile.chip ttsim
python3 -m baretile.chip check

In fish, activate the environment with . baretile-env/bin/activate.fish. chip ttsim downloads the release of ttsim that baretile is tested with, and chip check says what's missing and how to fix it. Then print the chip's firmware, clock, tiles and DRAM banks, and run a program on every worker:

python3 -m baretile.chip
python3 -m baretile.hello

On ttsim, which has 120 Tensix tiles, baretile.hello prints:

119 Tensix workers computed fib(30) = {832040}, and one tile dispatched the work

With no card on the PCI bus, baretile uses the simulator. On a machine with a Blackhole, it opens the card through tt-kmd, Tenstorrent's kernel driver, without root. Without tt-kmd, it opens the card through sysfs, which needs root. Read bring-up before running on a card.

Tensors

Tensor operations build an expression. Calling tolist() compiles it, runs it and copies the answer back to Python:

from baretile import pci
from baretile.chip import Chip
from baretile.runtime import Runtime
from baretile.tensor import Tensor

rt = Runtime(Chip(pci.open_device()))
x = Tensor.of(rt, [[1.0, 2.0], [3.0, 4.0]])
w = Tensor.of(rt, [[2.0, 0.0], [0.0, 3.0]])
print((x @ w).relu().tolist())
# [[2.0, 6.0], [6.0, 12.0]]

The matmul and ReLU run in one kernel: the ReLU works on the matmul's result in the math unit's registers, before it's written out. Tensors have up to five dimensions and support broadcasting, reductions, views and autograd, with bf16, fp32, int32, bfp8 and bfp4 storage.

Running a model

The models and the server also need NumPy. Install them, then serve a model by its Hugging Face ID:

python3 -m pip install 'baretile[models]'
python3 -m baretile.models.serve HuggingFaceTB/SmolLM-135M 8000

When it prints serving SmolLM-135M on port 8000, ask it for a completion from another terminal:

curl http://localhost:8000/v1/completions -H 'Content-Type: application/json' \
  -d '{"prompt": "The meaning of life is", "max_tokens": 4, "temperature": 0}'

The server speaks OpenAI's completions and chat completions API. On ttsim, a token takes about half a minute, since the simulator runs every core of the chip. The model docs list the models baretile runs, and cover training and the tinygrad device. We check the models against NumPy and transformers, and training against PyTorch.

Learning it

The ramps teach baretile from the top down. Each one is a script that explains its steps and checks its results. They're in the repository:

git clone https://github.com/baretile/baretile
cd baretile
python3 ramps/1_tensors.py   # tensor operations, fusion, formats, gradients and jit
python3 ramps/2_runtime.py   # C kernels on the workers, DRAM and the NoC
python3 ramps/3_tensix.py    # unpack, math and pack programs written by hand
python3 ramps/4_kernel.py    # a tensor operation of your own

The documentation explains the runtime, the compiler, the models and the hardware.
